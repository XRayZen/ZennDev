## はじめに

2025年8月、Docker Desktop(Windows/Mac)に重大な脆弱性CVE-2025-9074が発見されました。この脆弱性により、コンテナから簡単にホストシステムに侵入できてしまいます。本記事では、この脆弱性について初心者向けに簡単に解説します。

## 何が問題だったのか

Docker Desktopは内部で192.168.65.7:2375というアドレスを使ってDocker APIを公開していました。しかし、このAPIに**パスワードや認証が一切設定されていませんでした**。

つまり、コンテナ内から誰でも自由にDocker操作ができてしまう状況でした。

## 影響範囲

- **対象**: Docker Desktop for Windows/macOS
- **バージョン**: 4.44.3より古いバージョン
- **設定に関係なく影響あり**

特に被害が深刻なのはWindows

## 危険性評価

- 総合評価: クリティカル
- 想定CVSS v3.1 基本値: 9.8 (AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H)
- 根拠:
  - 未認証で TCP/2375 に到達可能 → PR:N, UI:N, AV:N
  - 特権コンテナ + ホスト bind mount によりスコープ変更と機密性/完全性/可用性が高影響 → S:C, C/I/A:H
  - 攻撃手順は Docker Engine API への少数の HTTP リクエストで成立 → AC:L
- 影響範囲:
  - ホストOS全体、他コンテナ、同一ネットワーク上の資産（資格情報窃取・横展開を含む）
- 実行権限:
  - 未認証（PR:N）。管理者権限は不要

## どのように攻撃されるのか

攻撃者がコンテナ内で悪意のあるプログラムを実行すると、以下のことが可能になります：

1. **新しいコンテナを勝手に作成**
2. **ホストのファイルシステム全体をマウント**
3. **機密情報が書かれたファイルの読み書き**

従来必要だった特別な設定（Dockerソケットマウント）が不要で、簡単に攻撃できてしまいます。

## 攻撃手法とSSRFの悪用

### ローカル攻撃の流れ
攻撃は非常にシンプルです：

1. **コンテナ内で悪意のあるプログラムを実行**
2. **内部のDocker APIに接続**
3. **ホスト全体をマウントした新しいコンテナを作成**
4. **ホストのファイルを自由に読み書き**

### SSRF経由でのリモート攻撃
特に危険なのが、**SSRF（Server-Side Request Forgery）を使ったリモート攻撃**です。以下のシナリオが考えられます：

1. **企業のWebアプリにSSRF脆弱性が存在**
   - URLパラメータで外部リソースを取得する機能
   - プロキシサービスやウェブスクレイピング機能

2. **外部攻撃者が悪意のあるURLを传送**
   - `http://vulnerable-webapp.com/fetch?url=http://192.168.65.7:2375/containers/create`
   - アプリが内部ネットワークのDocker APIにアクセス

3. **Webアプリがコンテナ作成リクエストを代行**
   - 攻撃者は直接Dockerにアクセスできなくても攻撃可能
   - ファイアウォールをパスして内部APIを操作

この手法により、**インターネットからでもDocker環境への侵入が可能**になります

## 被害の範囲

### ファイルアクセス
攻撃者はホストの以下にアクセス可能：
- DockerDesktopが実行されているアカウントでアクセスできるものは全て

### 開発環境への影響
特に開発者には以下のリスク：
- **ソースコードの窃取**
- **データベース情報の流出**
- **APIキーなどの認証情報窃取**
- **他のコンテナへの侵入**

## POCしてみた

この脆弱性の深刻度を理解するため、POC（Proof of Concept）コードを実装し実験しました。

### 実験環境
- Docker Desktop for Windows（脆弱性のあるバージョン）
- コンテナ内からの実行

### 実験結果
1. **Docker APIへの接続成功**
   - `http://192.168.65.7:2375/version` に認証なしでアクセス成功
   - Docker Engineのバージョン情報やシステム情報を取得

2. **特権コンテナの作成成功**
   - ホストのCドライブを`/host_root`にマウント
   - 特権モードでコンテナを起動

3. **ホストファイルシステムへの書き込み成功**
   - ホストのC:\直下に`cve_2025_9074_poc.txt`ファイルを作成
   - コンテナ内からホストのファイルやディレクトリ一覧を取得可能

## リスク（想定される悪用）

- ホストファイルシステムの読み書き（Docker Engineが実行されているアカウントの権限範囲内）
- 機密情報（パスワード、SSH鍵等）の窃取
- システム設定ファイルの改ざん
- マルウェアの設置、持続化
- 他コンテナ・ネットワークへの横展開

### 結果
この実験で、コンテナの隔離が完全に破られ、任意のホスト操作が可能であることが実証されました。

## 対策方法

### 即座に実施すべき対応

**Docker Desktopを最新版に更新**
1. Docker Desktopを開く
2. Settings（設定）を選択
3. Software Updatesから更新を実行
4. バージョン4.44.3以降であることを確認

現在のバージョンは「docker --version」コマンドで確認できます。

## まとめ

CVE-2025-9074は「コンテナ内部だから安全」という考えが間違いであることを示しました。

### 重要なポイント
1. コンテナ環境を過信しすぎないこと
